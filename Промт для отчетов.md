**Контекст:** Скрипт преобразует Markdown-файл в документ Word по шаблону. Требуется сгенерировать строго структурированный Markdown-код, который будет корректно обработан скриптом без ошибок. Визуальное отображение в чате значения не имеет.

**Цель:** Создать полный отчет по лабораторной работе с соблюдением требований ГОСТ 7.32-2001, структуры и форматирования.

---
## Строгие требования к оформлению Markdown-кода

### 1. Метаданные (обязательно в самом начале файла)

```markdown
[//]: # is_table=true
[//]: # teacher ="Иван Иванов"
```

---

### 2. Авторы и группа (строго сразу после метаданных)

```
__ФИО__: Швырев А.П, Скиба А.Р, Мусиенко А.Е
__Группа__: 090302-ИСТа-023
```

---

### 3. Заголовки

* Название работы — уровень `#`
* Тема работы — уровень `##`
* Все разделы — **только `####`**
* Запрещено использовать другие уровни заголовков
* Теоретическую часть не писать

---

### 4. Форматирование текста

* Запрещено:

  * жирный текст (`**`)
  * курсив через `*`
  * стандартные Markdown-списки (`-`, `*`)

* Разрешено:

  * использовать *подчеркивание* для курсива

* Обязательно выделяются:

  * все англоязычные термины (*IP*, *DHCP*, *ping*, *Cisco Packet Tracer* и т.д.)

* Стиль:

  * строго безличный
  * без "я", "мы"

* Абзацы:

  * один абзац = одна строка
  * между абзацами одна пустая строка

* Объем:

  * не менее 1000 слов

---

### 5. Перечисления (очень важно)

Запрещены стандартные списки Markdown.

Используется только такой формат:

```
Основной текст:
    - пункт,
    - пункт,
    - последний пункт.
```

Требования:

* перед подпунктом ровно 4 пробела
* используется обычный дефис
* в конце:

  * запятая — если есть продолжение
  * точка — у последнего пункта

Списки должны присутствовать в работе, но без избыточности.

---

### 6. Изображения (КРИТИЧЕСКИ ВАЖНО)

* Использовать несколько изображений (не менее 3 при наличии схемы и проверки)
* Каждое изображение должно быть логически обосновано
* Формат вставки:

```
Текст с упоминанием рисунка 1.

![Подпись](img/filename.png)
```

Требования:

* перед КАЖДЫМ изображением обязательно должна быть ссылка в тексте
* нумерация рисунков строго по порядку
* запрещено вставлять изображения без описания
* запрещено использовать одно изображение, если логически требуется несколько:

  * схема сети
  * адресация
  * проверка (ping)
  * этапы настройки (если уместно)

---

### 7. Структура отчета

Обязательные разделы:

* Цель работы
* Исходные данные
* Оборудование и ПО
* Ход выполнения работы
* Результаты работы
* Вывод

---

### 8. Содержательные требования

* Описывать процесс подробно
* Добавлять пояснения к каждому этапу
* Использовать списки там, где есть перечисления
* Добавлять описание:

  * топологии
  * адресации
  * настройки устройств
  * проверки сети
* Упоминать:

  * *IP-адрес*
  * *default gateway*
  * *ping*
  * *ARP*
  * интерфейсы (*GigabitEthernet*)

---

### 9. Частые ошибки (ИЗБЕГАТЬ)

* отсутствие ссылок на рисунки
* мало текста (менее 1000 слов)
* отсутствие списков
* использование Markdown-списков
* неправильные отступы
* отсутствие нескольких изображений
* использование "мы" или "я"

---

### 10. Важно

* Генерируется только Markdown-код
* Без пояснений вне кода
* Код должен быть сразу готов для обработки скриптом
* Структура и формат важнее визуального вида
