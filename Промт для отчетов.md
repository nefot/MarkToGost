# Промт: генерация отчёта по лабораторной работе (Markdown → DOCX по ГОСТ 7.32-2001)

## Контекст

Скрипт преобразует Markdown-файл в документ Word по шаблону ГОСТ 7.32-2001.
Задача — сгенерировать строго структурированный Markdown-код, который корректно обработается скриптом.
Визуальное отображение в чате значения не имеет. Важны только структура и формат.

---

## Метаданные

Обязательно в самом начале файла, до всего остального:

```
[//]: # is_table=true
[//]: # teacher ="Воробьев С.П."
[//]: # numerate = False
```

---

## Авторы

Сразу после метаданных, без пустой строки между ними:

```
__ФИО__: Швырев А.П, Скиба А.Р, Мусиенко А.Е
__Группа__: 090302-ИСТа-023
```

---

## Структура файла

Каждая лабораторная работа оборачивается в блок:

```
[//]: # ( Практическая работа №N){

...содержимое работы...

}
```

Заголовки используются строго в таком порядке:
- `#` — название работы
- `##` — тема работы
- `####` — все разделы внутри работы

Использование любых других уровней заголовков (`###`, `#####` и т.д.) **запрещено**.
Теоретическую часть не писать.

---

## Обязательные разделы (внутри блока работы)

В таком порядке:
1. Цель работы
2. Исходные данные
3. Оборудование и ПО
4. Ход выполнения работы
5. Результаты работы
6. Вывод

---

## Форматирование текста

### Запрещено
- Жирный текст: `**текст**`
- Курсив через звёздочку: `*текст*`
- Стандартные Markdown-списки: `- пункт` или `* пункт`

### Разрешено
- Курсив только через подчёркивание: `_текст_`

### Обязательно выделять курсивом
Все англоязычные термины: _IP_, _DHCP_, _ping_, _Decision Tree_, _Na_to_K_, _Jupyter Notebook_ и т.д.

### Стиль изложения
- Строго безличный: без "я", "мы"
- Один абзац = одна строка
- Между абзацами — одна пустая строка
- Объём — не менее 1000 слов

---

## Перечисления

Стандартные Markdown-списки запрещены. Единственный допустимый формат:

```
Основной текст:
    - пункт,
    - пункт,
    - последний пункт.
```

Правила:
- перед каждым пунктом ровно 4 пробела
- дефис обычный `-`
- запятая в конце каждого пункта, кроме последнего
- точка в конце последнего пункта
- списки должны присутствовать в тексте, но без избыточности

---

## Изображения

Минимум 3 изображения (схема, проверка, результат и т.п.).
Каждое изображение логически обосновано.

Формат вставки:

```
Текст с упоминанием рисунка N.

![Подпись к рисунку](img/filenameN.png)
```

Правила:
- перед каждым изображением обязательна ссылка в тексте
- нумерация рисунков строго по порядку: 1, 2, 3...
- подпись формируется автоматически из текста в `[]`, дублировать её ниже не нужно
- вставлять изображения без упоминания в тексте запрещено

---

## Частые ошибки — избегать

- Нет ссылки на рисунок перед изображением
- Менее 1000 слов
- Нет перечислений
- Использованы стандартные Markdown-списки (`-` или `*` в начале строки)
- Неправильные отступы в перечислениях (не 4 пробела)
- Менее 3 изображений
- Использованы "мы" или "я"
- Курсив через `*` вместо `_`
- Блок работы не обёрнут в `[//]: # ( Практическая работа №N){ ... }`

## Финальная инструкция

Генерируется только Markdown-код — без пояснений, комментариев и текста вне кода.
Код должен быть сразу готов для обработки скриптом.
