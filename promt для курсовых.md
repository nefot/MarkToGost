# есть скрипт, который преобразует файл markdown в docx по госту, есть четкий шаблон, который нужно соблюдать,
и есть четкие требования к оформлению. Я соблюдаю все эти требования, и в итоге получаю документ,
который соответствует ГОСТ 7.32-2001. Я могу использовать этот скрипт для создания документов для других лабораторных работ,
просто изменяя содержание и сохраняя шаблон.

---

**Контекст:** Скрипт преобразует Markdown-файл в документ Word по шаблону. Требуется сгенерировать строго структурированный Markdown-код, который будет корректно обработан скриптом без ошибок. Визуальное отображение в чате значения не имеет.
Сгенерируй документ в формате Markdown, строго соответствующий следующим правилам:



## 1. Общие требования

- Выводи ТОЛЬКО Markdown, без пояснений
- Не используй `markdown` блоки
- Соблюдай структуру для последующего парсинга в DOCX
- Используй русский язык
- Документ должен быть оформлен как курсовая работа по технической теме

---

### 3.2 Разделы через спец-синтаксис

Каждый основной раздел оформляется ТОЛЬКО так:

[//]: ### (1. Название раздела){
текст раздела
}

или без тела:
[//]: ### (2. Название)

---

### 3.3 Подразделы

Подразделы пишутся ОБЫЧНЫМИ заголовками:

#### 3.1 Название

#### 3.2 Название

(НО уровень определяется по номеру, а не по ####)

---

## 4. Введение и заключение

Пиши как обычные заголовки:

### ВВЕДЕНИЕ

текст...

### ЗАКЛЮЧЕНИЕ

текст...

(без [//]:)

---

## 5. Списки

Используй только:

- маркированные:

  - пункт

- нумерованные:

  1. пункт

---

## 6. Таблицы

Используй стандартный Markdown:

| Колонка | Колонка |
| ------- | ------- |
| текст   | текст   |

Перед таблицей можно писать:
Таблица 1 — Название

---

## 7. Курсив

Используй только:
-текст-

---

## 8. Изображения

Формат:
![Подпись](image.png)

---

## 9. Запрещено

❌ Не использовать:

- HTML
- произвольные комментарии
- другие форматы оглавления
- уровни заголовков как логику
-

- жирный текст (`**`)
- курсив через `-`
- стандартные Markdown-списки (`-`, `-`)

- Разрешено:

- использовать -подчеркивание- для курсива

- Обязательно выделяются:

- все англоязычные термины (-IP-, -DHCP-, -ping-, -Cisco Packet Tracer- и т.д.)

- Стиль:

- строго безличный
- без "я", "мы"

- Абзацы:

- один абзац = одна строка
- между абзацами одна пустая строка

### 6. Изображения (КРИТИЧЕСКИ ВАЖНО)

- Использовать несколько изображений (не менее 3 при наличии схемы и проверки)
- Каждое изображение должно быть логически обосновано
- Формат вставки:

```
Текст с упоминанием рисунка 1.

![Подпись](img/filename.png)
```

Требования:

- перед КАЖДЫМ изображением обязательно должна быть ссылка в тексте
- нумерация рисунков строго по порядку
- запрещено вставлять изображения без описания
- запрещено использовать одно изображение, если логически требуется несколько:

  - схема сети
  - адресация
  - проверка (ping)
  - этапы настройки (если уместно)

# Формулы в Markdown — инструкция

## Блочная формула (отдельная строка)

Формула оборачивается в `$$..$$` на отдельных строках.
Сразу после закрывающего `$$` — строки пояснения `где ...`:

```markdown
Закон Ньютона:

$$
F = m \cdot a
$$

где $F$ — сила (Н), $m$ — масса (кг), $a$ — ускорение (м/с²).
```

Пояснение может занимать несколько строк:

```markdown
$$
\sigma = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (x_i - \mu)^2}
$$

где $\sigma$ — среднеквадратичное отклонение,
$N$ — количество элементов,
$\mu$ — среднее значение выборки.
```

---

## Inline-формула (внутри текста)

Оборачивается в одиночные `$...$`:

```markdown
Уравнение $ax^2 + bx + c = 0$ имеет корни $x_{1,2}$.
```

---

## Часто используемые конструкции

| Что | LaTeX |
|---|---|
| Дробь | `\frac{числитель}{знаменатель}` |
| Корень | `\sqrt{x}` или `\sqrt[n]{x}` |
| Степень | `x^{2}` |
| Индекс | `x_{i}` |
| Сумма | `\sum_{i=1}^{n}` |
| Интеграл | `\int_{0}^{\infty}` |
| Греческие | `\alpha \beta \gamma \sigma \mu \lambda \omega \pi` |
| Большие греческие | `\Gamma \Delta \Sigma \Omega` |
| Умножение | `\cdot` или `\times` |
| Плюс-минус | `\pm` |
| Бесконечность | `\infty` |
| Стрелка | `\rightarrow \leftarrow \Rightarrow` |
| Скобки | `\left( ... \right)` |
| Матрица | `\begin{pmatrix} a & b \\ c & d \end{pmatrix}` |
| Определитель | `\begin{vmatrix} a & b \\ c & d \end{vmatrix}` |

---

## Полный пример

```markdown
## 1.1 Формулы

Квадратное уравнение $ax^2 + bx + c = 0$ решается по формуле:

$$
x_{1,2} = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
$$

где $a$, $b$, $c$ — коэффициенты уравнения.

Интеграл Гаусса:

$$
\int_{-\infty}^{+\infty} e^{-x^2} dx = \sqrt{\pi}
$$

Уравнение Шрёдингера:

$$
-\frac{\hbar^2}{2m} \nabla^2 \psi + V \psi = E \psi
$$

где $\hbar$ — постоянная Планка,
$m$ — масса частицы,
$\psi$ — волновая функция,
$V$ — потенциальная энергия,
$E$ — полная энергия.
```

---

## Важные правила

**Блочная формула:**
- `$$` всегда на отдельной строке
- пустая строка перед `$$` обязательна
- пояснение `где ...` идёт сразу после закрывающего `$$` без пустой строки — тогда оно привязывается к этой формуле
- пустая строка после пояснения отделяет следующий абзац

**Inline-формула:**
- не переносится на новую строку внутри `$...$`
- внутри пояснений `где $F$ — сила` рендерится как OMML автоматически



екомендации по работе со ссылками и списком литературы при заполнении Markdown-файла:

Общие правила оформления ссылок

В тексте документа используются только нумерованные ссылки в квадратных скобках:
1
, [2], [3] и т.д.

Нумерация должна быть сквозной и соответствовать порядку источников в разделе "Литература".

Ссылка ставится в конце смыслового фрагмента или предложения перед точкой.

Пример:
Данный стандарт определяет требования к кабельным системам [3].

Связь ссылок с разделом "Литература"

Каждая ссылка в тексте ОБЯЗАНА иметь соответствующую запись в списке литературы.

Номер ссылки в тексте должен совпадать с номером источника в списке.

Запрещено:

использовать ссылку без источника
добавлять источник без использования в тексте
Работа с электронными ресурсами

Электронные источники оформляются внизу раздела "Литература" в виде ссылок:

При этом в тексте используется только номер: 1

Важно:

не вставлять URL прямо в текст
не использовать круглые скобки вида (site.ru)
Порядок размещения источников

Список литературы формируется в следующем порядке:

Нормативные документы (ГОСТ, стандарты)
Международные стандарты (IEEE, RFC, TIA/EIA)
Книги и печатные издания
Электронные ресурсы

При этом нумерация НЕ меняется, если на источники уже есть ссылки в тексте.

Добавление новых источников

Если добавляется новый источник:

он получает следующий номер (например, было [1–10], станет [11])
ссылка на него должна быть добавлена в текст
нельзя вставлять источник "в середину" списка с изменением нумерации
Типичные ошибки

❌ Использование ссылок вида (1), {1}, или [1,2]
❌ Несоответствие нумерации
❌ Прямые URL в тексте
❌ Дублирование источников
❌ Упоминание "chatgpt", "AI" и т.п.

Проверка перед конвертацией в DOCX

Перед запуском скрипта необходимо убедиться:

все ссылки [n] существуют
нет "висячих" ссылок
нумерация последовательная (без пропусков)
все URL находятся только в разделе "Литература"
формат [n]: сохранен без изменений

Сгенерируй полноценный документ (5–10 страниц текста) по теме:
"Проектирование локальной вычислительной сети офиса"
