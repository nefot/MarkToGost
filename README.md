# MarkToGost

Конвертер Markdown → DOCX с оформлением по ГОСТ 7.32: отчёты, курсовые и выпускные работы пишутся
в обычном текстовом редакторе, а на выходе получается документ Word с оглавлением, нумерацией
страниц, рисунков, таблиц и формул.

Что умеет:

- поля, шрифт и интервалы по ГОСТ, автоматическое оглавление и нумерация страниц;
- разделы с новой страницы, заголовки с нумерацией из текста;
- таблицы Markdown и HTML (объединение ячеек, формулы), сквозная нумерация, повтор шапки на каждой
  странице, подписи «Продолжение таблицы N»;
- рисунки и схемы draw.io (экспорт страницы схемы прямо при сборке), альбомные листы для широких схем;
- формулы LaTeX, которые превращаются в редактируемые формулы Word, с нумерацией и пояснением «где …»;
- блоки кода, списки, курсив.

## Установка

Нужен Python 3.10 или новее.

```bash
pip install -r requirements.txt
```

Дополнительные программы — только для отдельных возможностей:

| Программа | Для чего | Где искать |
|---|---|---|
| [Pandoc](https://pandoc.org/installing.html) | формулы `$$ … $$` | в `PATH` |
| [draw.io Desktop](https://www.drawio.com/) | схемы `*.drawio` | `C:\Program Files\draw.io` или переменная `DRAWIO_PATH` |
| Microsoft Word | доводка документа скриптом `tools/finalize_docx.ps1` | Windows |

## Быстрый старт

1. Положите Markdown-файл в папку `input/`, например `input/report.md`:

   ```markdown
   [//]: # (ОГЛАВЛЕНИЕ )

   [//]: ### (ВВЕДЕНИЕ){
   Цель работы — …
   }

   [//]: ### (1. АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ){
   ### 1.1 Описание предметной области

   Текст раздела. Подробнее — на рисунке 1.

   ![Структура системы](img/scheme.drawio#1)

   Таблица — Участники процесса
   | Роль | Задача |
   |---|---|
   | Заказчик | оформляет заказ |
   }
   ```

2. Соберите документ:

   ```bash
   python -m MarkToGost.main report.md
   ```

   Результат — `output/report.docx`. Без имени файла обрабатываются все `.md` из `input/`.

3. Необязательно, но рекомендуется для итоговой версии (Windows + Word):

   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\finalize_docx.ps1 output\report.docx -Pdf output\report.pdf
   ```

   Скрипт обновляет оглавление, расставляет подписи «Продолжение таблицы N» по фактическим
   границам страниц и сохраняет PDF.

Полный синтаксис — в [docs/syntax.md](docs/syntax.md).

## Параметры командной строки

```bash
python -m MarkToGost.main [файл.md] [--output имя.docx] [параметры оформления]
```

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--output`, `-o` | имя входного файла | имя DOCX в папке `output/` |
| `--font-name` | Times New Roman | шрифт текста |
| `--font-size` | 14 | размер шрифта текста, pt |
| `--line-spacing` | 1.5 | межстрочный интервал |
| `--first-line-indent` | 1.25 | абзацный отступ, см |
| `--use-first-line-indent` | true | включить абзацный отступ |
| `--left-margin`, `--right-margin` | 3.0, 1.0 | поля слева и справа, см |
| `--top-margin`, `--bottom-margin` | 2.0, 2.0 | поля сверху и снизу, см |
| `--image-width` | 0.70 | ширина рисунка как доля ширины текста |
| `--caption-font-size` | 12 | размер шрифта подписей рисунков, pt |
| `--caption-italic` | true | курсив в подписях рисунков |
| `--table-font-size` | 12 | размер шрифта таблиц, pt (уменьшается до 10 pt, если таблица не помещается) |
| `--code-font-size` | как у текста | размер шрифта блоков кода, pt |
| `--code-line-spacing` | как у текста | межстрочный интервал блоков кода |

Значения по умолчанию заданы в `MarkToGost/config.py`.

## Структура репозитория

```
MarkToGost/            пакет конвертера
├── main.py            точка входа и сборка документа
├── config.py          параметры оформления по умолчанию
├── formula_renderer.py LaTeX → формулы Word через Pandoc
├── parser/            Markdown → список блоков
├── renderer/          блоки → DOCX
├── utils/             форматирование, оглавление, таблицы, draw.io
└── tests/             тесты pytest
docs/                  документация
examples/blocks/       примеры каждого вида блока
tools/                 вспомогательные скрипты
input/                 ваши Markdown-файлы (не хранятся в git)
output/                собранные документы (не хранятся в git)
```
