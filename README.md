# Руководство пользователя: Конвертер Markdown в DOCX по ГОСТ 7.32-2001

## Описание программы

Эта программа предназначена для пакетного конвертирования файлов Markdown (.md) в документы Microsoft Word (.docx) в соответствии с требованиями ГОСТ 7.32-2001. Программа поддерживает автоматическое создание оглавления, нумерацию элементов, правильное форматирование заголовков, таблиц, изображений и списков.


# ПОСЛЕ ГЕНЕРАЦИИ ФАЙЛА НЕОБХОДИМО В WORD ФАЙЛЕ НАЖАТЬ Ctrl + A → F9, ЧТОБЫ СОЗДАТЬ ОГЛАВЛЕНИЕ И НУМЕРАЦИЮ."
## Основные возможности

- **Автоматическое оглавление**: Создаётся на основе уровней заголовков и нумерации.
- **Поддержка разделов**: Специальный синтаксис для разделов документа.
- **Форматирование по ГОСТ**: Корректные поля, шрифты, отступы.
- **Нумерация элементов**: Автоматическая нумерация таблиц и рисунков.
- **Поддержка Markdown**: Заголовки, списки, таблицы, изображения, блоки кода.

## Требования

- **Python 3.7+**
- **Библиотеки**:
  - `python-docx` (установите командой `pip install python-docx`)

## Установка

1. Убедитесь, что Python установлен.
2. Установите необходимые библиотеки:
   ```
   pip install python-docx
   ```
3. Скачайте файл `md_to_gost_block.py` и поместите его в папку с вашими .md файлами.

## Запуск программы

1. Поместите .md файлы в ту же папку, что и `md_to_gost_block.py`.
2. Откройте командную строку (терминал) в этой папке.
3. Запустите скрипт:
   ```
   python md_to_gost_block.py
   ```
4. Программа обработает все .md файлы и создаст соответствующие .docx файлы.

## Формат Markdown файлов

### Основные элементы

- **Заголовки**: `# Заголовок 1`, `## Заголовок 2`, `### Заголовок 3`, `#### Заголовок 4`
- **Текст**: Обычный текст с автоматическими отступами.
- **Курсив**: `_текст_`
- **Списки**: `- элемент` или `1. элемент`
- **Таблицы**: Стандартный Markdown синтаксис.
- **Изображения**: `![Подпись](путь/к/изображению.png)`
- **Блоки кода**: ```language\nкод\n```

### Специальные разделы

Программа поддерживает специальные разделы для структурирования документа:

- `[//]: # (Название раздела)` - Раздел без содержимого.
- `[//]: #### (Название раздела)[new_page=false]` - Раздел с параметрами.
- Разделы с содержимым:
  ```
  [//]: #### (Введение) {
  ## Подраздел
  Текст...
  }
  ```

### Метаданные

- **ФИО и группа**: Вставьте в текст `__ФИО: Иван Иванов__` и `__Группа: 12345__`.
- **Таблица подписей**: Добавьте `[//]: # is_table = true` для создания таблицы с ФИО и проверяющим.
- **Преподаватель**: `[//]: # teacher = "Иванов И.И."`

### Нумерация заголовков

Заголовки могут иметь нумерацию для правильного оглавления:
- `#### 1. Введение`
- `#### 1.1. Подраздел`
- `#### 2. Глава`

#### Теоретическая часть

Разъём RJ45 (8P8C) — стандартный коннектор для сетевых кабелей Ethernet. Кабели витая пара бывают экранированные (STP) и неэкранированные (UTP). При сборке кабеля важно соблюдать один из стандартов распиновки: T568A или T568B. В большинстве современных локальных сетей используется T568B.

Распиновка T568B (вид снизу разъёма, контакты слева направо):
1 — бело-оранжевый
2 — оранжевый
3 — бело-зелёный
4 — синий
5 — бело-синий
6 — зелёный
7 — бело-коричневый
8 — коричневый
![Распиновка T568B](img/img_3.png)
Пары в кабеле предназначены для минимизации наводок и перекрёстных помех за счёт витков; при обжиме важно не расплетать пары дальше рекомендуемой длины (обычно не более 12 мм) и сохранять порядок проводников.

Качество обжима влияет на скорость и стабильность соединения. Неплотный контакт, неправильная последовательность проводов или повреждение изоляции может привести к обрывам, коротким замыканиям или снижению характеристик канала.

   - Я подготовил кримпер, стриппер, тестер и разъёмы RJ45.
   - Я убедился, что использую разъёмы, соответствующие типу кабеля (UTP/STP) и категории (Cat5e/Cat6).

2. Снятие внешней изоляции
   - Я отмерил необходимую длину кабеля и оставил запас 5–10 см для удобства работы.
   - Я снял внешнюю оболочку кабеля стриппером на длину ≈12 мм от конца, чтобы оголить витые пары.
   - Я аккуратно следил, чтобы не повредить изоляцию пар.

   ![Снятие оболочки](img/img_2.png)
3. Расплетение и выравнивание пар
   - Я осторожно расплёл пары и выпрямил отдельные проводники.
   - Я не расплетал пары более чем на 10–12 мм, чтобы не ухудшить помехозащищённость.

4. Выбор распиновки и выравнивание проводников
   - Для получения прямого кабеля я применил схему T568B на обоих концах.
   - Я разложил провода в нужном порядке (см. выше) и выровнял их по длине.

   Пример порядка (T568B):
   - бело-оранжевый, оранжевый, бело-зелёный, синий, бело-синий, зелёный, бело-коричневый, коричневый

5. Обрезка проводников
   - Удерживая провода плотно вместе, я отрезал их ровно под прямым углом так, чтобы свободная длина проводников была ≈12 мм от края оболочки.
   - Я проверил, чтобы все проводники имели одинаковую длину.

6. Вставка проводников в разъём RJ45
   - Я расположил разъём так, чтобы контактная пластина смотрела в нужную сторону, и вставил выровненные проводники в разъём до упора; оболочка кабеля вошла внутрь разъёма на 1–2 мм для надёжной фиксации.

   ![Вставка в разъём](img/img_1.png)
7. Обжим (кримпинг)

   - Инструмент прижал контакты к проводникам и зажал пластиковую защёлку разъёма.

   ![Обжим разъёма](img/img.png)

## Особенности

- **Автоматическое оглавление**: Вставляется в раздел "ОГЛАВЛЕНИЕ" и включает все заголовки с уровнями 1-9.
- **Форматирование заголовков**: Уровень 1 - по центру, заглавными буквами. Остальные - по левому краю с отступами.
- **Нумерация**: Таблицы и рисунки нумеруются автоматически.
- **Страницы**: Разрывы страниц между разделами.
- **Номера страниц**: В нижнем колонтитуле.

## Устранение проблем

- **Файл не конвертируется**: Проверьте синтаксис Markdown.
- **Изображения не вставляются**: Убедитесь, что пути к изображениям корректны.
- **Оглавление пустое**: Проверьте нумерацию заголовков.
- **Ошибка сохранения**: Закройте .docx файл в Word перед запуском.
