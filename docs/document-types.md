# Типы документов

У каждого вида документа — курсовой, ВКР, отчёта по практике, реферата, договора — своё
оформление, состав разделов и титульный лист. Всё это хранится в **профиле** типа. В самом
документе указывается только тип и то, что относится именно к нему: тема, руководитель,
отличающиеся параметры.

## Быстрый старт

```bash
python -m MarkToGost.main --types                    # какие типы есть
python -m MarkToGost.main --new курсовая моя.md      # заготовка input/моя.md
python -m MarkToGost.main моя.md --pdf               # сборка, доводка в Word, PDF
```

Заготовка уже содержит шапку с полями титульного листа и разделы в нужном порядке:

```markdown
---
тип: курсовая
дисциплина: Базы данных
тема: Проектирование базы данных платформы 3D-печати
руководитель: Петров П. П.
---

# ВВЕДЕНИЕ

Текст введения.

# 1 АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

## 1.1 Описание предметной области

…

# ЗАКЛЮЧЕНИЕ

# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ

# ПРИЛОЖЕНИЕ А
```

Что делает MarkToGost по профилю:

- применяет оформление типа (шрифт, поля, интервалы, размеры подписей, таблиц и кода);
- собирает титульный лист из шаблона и подставляет в него поля из шапки;
- вставляет содержание (у ВКР — после реферата);
- превращает каждый заголовок `# …` в структурный элемент или раздел с новой страницы;
- проверяет состав разделов и заполнение титульного листа и выводит замечания:

  ```
  ✅ input\моя.md → output\моя.docx
     ⚠️ нет обязательного раздела «ЗАКЛЮЧЕНИЕ»
     ⚠️ не заполнено поле титульного листа «руководитель»
  ```

Документ без шапки собирается как раньше — с параметрами по умолчанию и разметкой
`[//]: ### (…){ … }` (см. [syntax.md](syntax.md)).

## Встроенные типы

| Тип (`тип:`) | Титульный лист | Содержание | Структура |
|---|---|---|---|
| `гост`, `отчёт` | нет | да | любая |
| `курсовая` | курсовая работа (+ лист `задание`) | да | ВВЕДЕНИЕ → разделы с номером → ЗАКЛЮЧЕНИЕ → СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ → ПРИЛОЖЕНИЯ |
| `вкр`, `диплом` | ВКР с «Допустить к защите» (+ лист `задание`) | после реферата | РЕФЕРАТ → ВВЕДЕНИЕ → разделы → ЗАКЛЮЧЕНИЕ → СПИСОК → ПРИЛОЖЕНИЯ |
| `практика` | отчёт по практике | да | как у курсовой |
| `реферат` | реферат | да | ВВЕДЕНИЕ → разделы → ЗАКЛЮЧЕНИЕ → СПИСОК |
| `договор`, `соглашение` | нет | нет | любая; разделы идут подряд, без новых страниц |

Список источников может называться и «Библиографический список», «Список литературы»,
«Литература»; реферат ВКР — «Аннотация». Приложения необязательны.

### Поля титульного листа

| Тип | Обязательные поля | Необязательные |
|---|---|---|
| `курсовая`, `реферат` | вуз, кафедра, дисциплина, тема, студент, группа, руководитель, город | факультет, должность_руководителя, министерство, вид_работы, год |
| `вкр` | вуз, кафедра, направление, тема, студент, группа, руководитель, заведующий, город | профиль, консультант, нормоконтроль, факультет, должность_руководителя, министерство, вид_работы, год |
| `практика` | вуз, кафедра, вид_практики, организация, сроки, студент, группа, руководитель, город | руководитель_от_организации, факультет, министерство, год |

- `год` по умолчанию — текущий; `министерство` — «Министерство науки и высшего образования
  Российской Федерации»; `вид_работы` — «КУРСОВАЯ РАБОТА», «РЕФЕРАТ» и т. п. (можно написать
  «КУРСОВОЙ ПРОЕКТ»).
- `вид_практики` пишется в родительном падеже: «о прохождении **производственной** практики».
- Лист `задание` (курсовая, ВКР) дополнительно использует поля `направление`, `заведующий`,
  `исходные_данные`, `разделы_записки`, `графический_материал`, `дата_выдачи`, `срок_сдачи`;
  обязательны для него тема, студент, руководитель и (для курсовой) дисциплина, (для ВКР)
  заведующий. Заготовка `--new` перечисляет эти поля в комментариях шапки.
- Строка титульного листа с незаполненным необязательным полем просто не выводится.
- `титульный_лист: нет` — собрать документ без титульного листа (например, если он оформлен
  отдельно); `титульный_лист: мой_титул.docx` — использовать свой шаблон (путь относительно
  документа).

## Общие данные: marktogost.yaml

Вуз, кафедра, ФИО и группа одинаковы во всех ваших документах. Чтобы не повторять их,
создайте файл `marktogost.yaml` в корне проекта (или рядом с документами):

```yaml
вуз: Южно-Российский государственный политехнический университет (НПИ) имени М. И. Платова
кафедра: Программное обеспечение вычислительной техники
город: Новочеркасск
студент: Иванов И. И.
группа: ПИб-21
```

Пример — [examples/marktogost.yaml](../examples/marktogost.yaml). Значения применяются в таком
порядке, каждое следующее сильнее предыдущего:

1. профиль типа;
2. `marktogost.yaml` в корне проекта;
3. `marktogost.yaml` в папке документа;
4. шапка документа;
5. параметры командной строки (`--font-size`, `--code-font-size`…).

Заготовка `--new` не включает в шапку поля, которые уже заданы в `marktogost.yaml`.

## Параметры оформления

Любой параметр можно переопределить в шапке документа — на верхнем уровне или в разделе
`оформление:`:

```yaml
---
тип: курсовая
тема: …
размер_шрифта_кода: 9
оформление:
  интервал: 1.0
---
```

| Параметр | Значение в ГОСТ-профиле | Смысл |
|---|---|---|
| `шрифт` | Times New Roman | шрифт текста |
| `размер_шрифта` | 14 | размер текста, pt |
| `интервал` | 1.5 | межстрочный интервал |
| `отступ_абзаца` | 1.25 | абзацный отступ, см |
| `красная_строка` | true | включить абзацный отступ |
| `поле_слева`, `поле_справа` | 3.0, 1.0 | поля, см |
| `поле_сверху`, `поле_снизу` | 2.0, 2.0 | поля, см |
| `ширина_рисунков` | 1.0 | ширина рисунка, доля ширины текста |
| `размер_подписей` | 12 | размер подписей рисунков, pt |
| `курсив_подписей` | false | курсив в подписях рисунков |
| `размер_шрифта_таблиц` | 12 | размер текста таблиц, pt |
| `размер_шрифта_кода` | 10 | размер текста блоков кода, pt |
| `интервал_кода` | 1.0 | интервал блоков кода |
| `нумерация_страниц` | true | номера страниц внизу по центру |
| `содержание` | true | вставлять содержание |
| `заголовок_содержания` | СОДЕРЖАНИЕ | заголовок содержания |
| `разделы_с_новой_страницы` | true | `# Заголовок` начинает новую страницу |

Неизвестный параметр в разделе `оформление:` не ломает сборку, но выводится в замечаниях —
так видны опечатки. Неизвестный ключ на верхнем уровне шапки считается полем титульного листа.

## Вставные листы: титульный, задание, отзыв и другие

Вставной лист — документ Word с полями `{{имя}}`, который MarkToGost заполняет и вставляет
в нужное место. Титульный лист — тоже вставной лист, всегда первый. Каждый лист начинается
с новой страницы и сохраняет свою вёрстку: размер и поля страницы, стили, рисунки (например,
герб вуза).

### Где лист появится

**Листы профиля.** В профиле могут быть описаны готовые листы; их включают по имени.
У курсовой и ВКР есть лист `задание` (задание на работу по форме кафедры) — он встаёт сразу
после титульного листа:

```yaml
---
тип: курсовая
листы: [задание]
заведующий: Сидоров С. С.
исходные_данные: |
  Предметная область — платформа заказа 3D-печати.
  СУБД — PostgreSQL.
разделы_записки:
  - Введение
  - 1 Анализ предметной области
  - Заключение
дата_выдачи: 14.09.2026
срок_сдачи: 25.12.2026
---
```

**Свои листы в шапке** — словарь с шаблоном и местом:

```yaml
листы:
  - задание
  - шаблон: отзыв.docx            # путь относительно документа
    перед: ПРИЛОЖЕНИЕ
    номер_страницы: нет
  - шаблон: нормоконтроль.docx
    место: конец
```

| Ключ | Значение |
|---|---|
| `шаблон` | файл `.docx`: относительно документа, абсолютный путь или файл из `profiles/titles/` |
| `после: X` | после раздела X, после листа (`после: титульный лист`) или после содержания (`после: содержание`) |
| `перед: X` | перед разделом X; заголовок сравнивается по началу, поэтому `ПРИЛОЖЕНИЕ` — первое приложение |
| `место: начало` / `место: конец` | в начале документа (после уже вставленных первых листов) или в самом конце |
| `номер_страницы: нет` | не печатать номер на первой странице листа (страница всё равно учитывается) |
| `обязательные_поля` | поля листа, без которых выводится замечание |
| `имя` | имя листа для замечаний и для `после: <имя листа>`; по умолчанию — имя файла |

Если раздела, к которому привязан лист, в документе нет, лист не вставляется, а в замечаниях
это указывается.

**Прямо в тексте** — отдельной строкой в нужном месте документа:

```markdown
{{лист: шаблоны/справка.docx}}
{{лист: шаблоны/справка.docx | без номера}}
```

### Заполнение полей

- Поле в шаблоне записывается как `{{имя}}`, например `на тему «{{тема}}»`. Имя любое:
  значение берётся из шапки документа, `marktogost.yaml` или профиля. Поле, которого нигде
  нет, попадает в замечания.
- Многострочное значение пишется блоком YAML `|`, а список (`- пункт`) выводится по пункту
  на строку — так заполняются «Исходные данные», «Разделы пояснительной записки» и т. п.
- Строка шаблона (абзац или строка внутри абзаца, разделённая переносом Shift+Enter),
  в которой поле оказалось пустым, удаляется целиком. Поэтому подпись и значение, которое
  может отсутствовать, лучше ставить на разные строки.
- Имя поля не должно разрываться форматированием: `{{тема}}` целиком одним начертанием.

### Свой шаблон

Стандартные шаблоны лежат в `MarkToGost/profiles/titles/` — это обычные документы Word.
Откройте нужный, переделайте под методичку своего вуза и сохраните. Шаблон можно не класть
в пакет, а указать путь в шапке: `титульный_лист: шаблоны/мой_вуз.docx`;
`титульный_лист: нет` собирает документ без титульного листа.

Ограничения: колонтитулы шаблона в документ не переносятся (номера страниц общие для всего
документа), а автоматическая нумерация списков Word в шаблоне превращается в обычный текст —
нумеруйте пункты вручную.

Недостающие стандартные шаблоны создаёт `python tools/make_title_templates.py`. Существующие
файлы он не трогает; `--force` пересоздаёт все, и правки, сделанные в Word, при этом теряются.

## Свой тип документа

Добавьте YAML-файл в `MarkToGost/profiles/`, например `laba.yaml`:

```yaml
наследует: гост
имена: [лабораторная, лабораторная работа]
название: Лабораторная работа
описание: Отчёт о лабораторной работе

титульный_лист:
  шаблон: laba.docx                  # файл в profiles/titles/
  обязательные_поля: [вуз, кафедра, дисциплина, номер, тема, студент, группа, руководитель, город]

поля:                                # значения по умолчанию
  вид_работы: ОТЧЁТ О ЛАБОРАТОРНОЙ РАБОТЕ

оформление:                          # только отличия от профиля-основы
  содержание: false

структура:
  - элемент: ЦЕЛЬ РАБОТЫ
  - основная_часть                   # разделы с номером: «1 …», «2 …»
  - элемент: ВЫВОДЫ
    синонимы: [ЗАКЛЮЧЕНИЕ]
  - элемент: ПРИЛОЖЕНИЕ
    по_началу: true                  # ПРИЛОЖЕНИЕ А, ПРИЛОЖЕНИЕ Б…
    обязательный: false
```

Ключи профиля:

| Ключ | Смысл |
|---|---|
| `наследует` | профиль-основа; словари сливаются, списки и значения заменяются |
| `имена` | как тип можно писать в `тип:`; регистр и «ё» не важны |
| `название`, `описание` | для `--types` |
| `оформление` | параметры из таблицы выше |
| `титульный_лист.шаблон` | файл в `profiles/titles/` |
| `титульный_лист.обязательные_поля` | поля, без которых выводится замечание |
| `поля` | значения полей по умолчанию; `текущий год` — подставляется год сборки |
| `листы` | именованные вставные листы: `имя: {шаблон, после/перед/место, номер_страницы, обязательные_поля, включён}`; `включён: да` — лист вставляется без упоминания в шапке |
| `структура` | структурные элементы по порядку |

Элемент структуры — строка с заголовком, `основная_часть` или словарь:

| Ключ элемента | Смысл |
|---|---|
| `элемент` | заголовок элемента |
| `синонимы` | другие допустимые заголовки |
| `обязательный` | по умолчанию `true` |
| `перед_содержанием` | элемент идёт до содержания (реферат ВКР) |
| `по_началу` | совпадение по началу заголовка (приложения) |
