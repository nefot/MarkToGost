# Устройство конвертера

## Конвейер

```
            шапка ---  ──► профиль типа + marktogost.yaml + шапка ──► DocumentSettings, поля
               │                                                        │
Markdown ──────┴► parser ──► блоки ──► structure ──► renderer ──► DOCX ─┴► вставные листы
                                       (разделы, содержание,            (титульный, задание…:
                                        места листов, проверки)          шаблоны с полями {{…}})
```

`main.create_document(md_text, base_dir, warnings)` выполняет всю сборку:

1. `parser.frontmatter.split_front_matter` отделяет YAML-шапку `--- … ---`. Нет шапки —
   документ собирается без профиля с параметрами `config.DocumentSettings`, как в ранних версиях.
2. С шапкой: `profiles.load_profile` загружает профиль типа (с наследованием), поверх него
   сливаются `marktogost.yaml` из корня проекта и папки документа и сама шапка
   (`profiles.split_settings` делит их на оформление и поля титульного листа). Параметры
   оформления записываются в `DocumentSettings` на время сборки (`main.settings_scope`),
   флаги командной строки применяются последними.
3. `parser.metadata.extract_metadata` читает старые служебные строки (`numerate`,
   `use_headings`, `is_table`, ФИО, группа) и они вырезаются из текста.
4. Создаётся пустой документ: поля страницы и стили из `DocumentSettings`. Из профиля и шапки
   собирается список вставных листов (`main._sheet_specs`): титульный лист, листы профиля,
   листы из ключа `листы`.
5. `parser.MarkdownParser.parse` превращает текст в блоки (`parser/blocks.py`).
6. По профилю (`structure.py`): заголовки `# …` собираются в разделы (`group_sections`),
   вставляется содержание (`insert_toc`), состав и порядок разделов и заполнение полей
   сверяются с профилем, листы расставляются блоками `SheetBlock` по своим местам
   (`place_sheets`). Замечания попадают в `warnings`.
7. `renderer.DocumentRenderer` отрисовывает блоки; в конце — таблица подписей (`is_table`)
   и номера страниц.

`main.process_md_file` находит файл (путь или имя в `input/`), сохраняет результат в `output/`,
печатает замечания и при `--finalize`/`--pdf` запускает доводку `tools/finalize_docx.ps1`.

## Блоки

| Блок | Markdown | Рендерер |
|---|---|---|
| `Section` | `[//]: ### (Название){ … }` | `renderer/section.py` |
| `HeadingBlock` | `### 1.1 Название` | `renderer/text.py` |
| `TextBlock` | абзац | `renderer/text.py` |
| `ListBlock` | `- пункт`, `1. пункт` | `renderer/list_.py` |
| `TableBlock` | таблица Markdown с подписью | `renderer/table.py` |
| `HtmlTableBlock` | `<table>…</table>` | `renderer/html_table.py` |
| `ImageBlock` | `![подпись](путь){#id landscape}` | `renderer/image.py` |
| `FormulaBlock` | `$$ … $$` и пояснение «где …» | `renderer/formula.py` |
| `CodeBlock` | ```` ``` ```` | `renderer/code.py` |

Блоки — простые `dataclass` без логики. Парсер идёт по строкам: для каждого вида блока есть
пара методов `_is_…` (распознать начало) и `_parse_…` (прочитать блок и сдвинуть `self.index`).
Раздел собирает вложенные блоки до своей закрывающей `}`.

## Рендеринг

`DocumentRenderer` — диспетчер: словарь «тип блока → функция `render_…(renderer, block)`».
Функции получают сам рендерер и через него — документ и общее состояние:

- счётчики `table_counter`, `figure_counter`, `formula_counter` — сквозная нумерация;
- `image_refs` — номера рисунков по `#id` для замены ссылок `@id` в тексте;
- отложенный разрыв страницы и признак открытого альбомного раздела (см. ниже).

### Разрывы страниц

Раздел начинается и заканчивается разрывом страницы, но разрыв не вставляется отдельным
абзацем. `_safe_page_break` запоминает место, а следующий отрисованный абзац получает свойство
«с новой страницы» (`w:pageBreakBefore`). Так не появляются пустые страницы, если предыдущая
заполнена до конца, и не растягивается последняя строка абзаца перед разрывом. Разрыв, после
которого ничего не отрисовано (конец документа), просто не применяется.

### Альбомные рисунки

Рисунок с атрибутом `landscape` закрывает текущий раздел DOCX (свойства раздела переносятся
в последний абзац) и открывает новый — альбомный. Следующие альбомные рисунки остаются в нём,
каждый со своей страницы; первый же блок другого типа возвращает книжную ориентацию.
Ширина рисунка ограничивается и шириной страницы, и высотой, чтобы рисунок с подписью
поместился на лист.

### Таблицы

Таблица выводится целиком, страницы для неё вычисляет Word: строка заголовка помечена как
повторяемая, строки не разрываются, подпись и заголовок «держатся» с первой строкой данных.
Ширина колонок считается по содержимому (`_column_widths_cm`): каждая колонка не уже самого
длинного слова, остаток распределяется пропорционально объёму текста; при нехватке ширины
шрифт уменьшается до 10 pt (`_table_font_size`).

Подписи «Продолжение таблицы N» требуют знания фактической вёрстки, поэтому их ставит
`tools/finalize_docx.ps1` через Word: находит строку, с которой таблица переходит на новую
страницу, делит таблицу, вставляет подпись и копию заголовка.

### Вставные листы

`SheetBlock` появляется в блоках из профиля и шапки (`place_sheets`) или из строки
`{{лист: …}}` в тексте. `renderer/sheets.py` открывает шаблон, подставляет поля (строка
с пустым полем удаляется, многострочные значения превращаются в переносы) и вставляет
содержимое отдельным разделом DOCX: перед листом завершается текущий раздел, свойства
страницы листа берутся из шаблона, после листа основная часть продолжается с новой страницы.
Стили, на которые ссылается лист, копируются в документ вместе с цепочкой `basedOn`, рисунки —
заново добавляются в пакет документа. Колонтитулы и нумерация списков шаблона не переносятся.

Свойства раздела DOCX хранятся в служебном абзаце высотой 1 pt (`utils.xml_helpers.end_section_here`):
если записать их в последний абзац текста, Word растянет его последнюю строку по ширине.
Тот же механизм используют альбомные рисунки.

### Схемы draw.io

`utils/drawio.py` экспортирует нужную страницу `.drawio` в PNG через CLI draw.io Desktop
и кеширует результат в `output/.drawio_cache` с учётом времени изменения файла схемы.

### Формулы

`formula_renderer.py` передаёт LaTeX в Pandoc, получает DOCX с формулой в формате OMML и
переносит узел формулы в документ — формула остаётся редактируемой в Word. Без Pandoc
формулы не отрисовываются; проверить окружение: `python MarkToGost/formula_renderer.py`.

## Модули

```
MarkToGost/
├── main.py               сборка документа, CLI (--new, --types, --finalize, --pdf)
├── config.py             DocumentSettings, DrawioSettings, CaptionSettings
├── structure.py          разделы из «# …», содержание, проверка по профилю
├── profiles/             профили типов (*.yaml), загрузчик, шаблоны titles/*.docx
├── formula_renderer.py   LaTeX → OMML через Pandoc
├── parser/
│   ├── blocks.py         dataclass-блоки
│   ├── markdown_parser.py
│   ├── frontmatter.py    YAML-шапка документа
│   └── metadata.py       служебные флаги, ФИО, группа
├── renderer/
│   ├── document_renderer.py  диспетчер, разрывы страниц
│   ├── section.py  text.py  list_.py  table.py  html_table.py
│   ├── image.py  formula.py  code.py
│   ├── sheets.py         вставные листы: заполнение полей, перенос стилей и рисунков
│   └── base.py           протокол функции рендеринга
├── utils/
│   ├── formatting.py     шрифты, абзацы, курсив и экранирование \_
│   ├── toc.py            оглавление, стили и уровни заголовков
│   ├── document_helpers.py  разбор строк таблиц, подписи
│   ├── html_table_parser.py
│   ├── xml_helpers.py    границы таблиц, повтор заголовка, номера страниц
│   └── drawio.py         экспорт схем
└── tests/
tools/
├── finalize_docx.ps1     доводка в Word: оглавление, продолжения таблиц, PDF
├── check_blocks.py       сборка примеров из examples/blocks
└── make_title_templates.py  стартовые шаблоны титульных листов
```

Зависимости направлены сверху вниз: `main` → `structure`, `renderer` → `parser`, `profiles` →
`utils` → `config`.
Нижние слои не импортируют верхние.
