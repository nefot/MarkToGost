# Синтаксис документа

MarkToGost понимает упрощённый Markdown с несколькими расширениями для оформления по ГОСТ.
Примеры каждого вида блока — в папке [examples/blocks](../examples/blocks).

## Структура документа

### Документ с шапкой (рекомендуется)

Если документ начинается с шапки `---` с типом документа (см.
[document-types.md](document-types.md)), каждый заголовок первого уровня `# …` начинает
структурный элемент или раздел, а всё до следующего `# …` входит в него:

```markdown
---
тип: курсовая
тема: …
---

# ВВЕДЕНИЕ

Текст введения.

# 1 АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

## 1.1 Описание предметной области
```

Раздел начинается с новой страницы (у договора — нет, это задаёт профиль). Содержание
вставляется автоматически; если нужно поставить его в определённое место, напишите там
`[//]: # (СОДЕРЖАНИЕ )`.

### Разделы в служебной разметке

В документе без шапки (и при желании в документе с шапкой) раздел открывается служебной
строкой и закрывается строкой `}`:

```markdown
[//]: ### (1. АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ){
Текст раздела, подзаголовки, таблицы, рисунки…
}
```

- Раздел начинается с новой страницы.
- Текст в скобках становится заголовком раздела; номер пишется прямо в тексте (`1.`, `2.` …),
  уровень заголовка определяется этим номером (см. [заголовки](#заголовки)). Число решёток
  в служебной строке на уровень не влияет. Разделы без номера (ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ,
  ПРИЛОЖЕНИЕ А) — заголовки первого уровня.
- В названии раздела нельзя использовать круглые скобки: `)` закрывает название.
- Чтобы раздел не начинался с новой страницы, добавьте `[new_page=false]` перед `{`:
  `[//]: ### (1.2 Подраздел)[new_page=false]{`.
- Закрывающая `}` должна стоять на отдельной строке.

Оглавление вставляется строкой `[//]: # (ОГЛАВЛЕНИЕ )` или `[//]: # (СОДЕРЖАНИЕ )` (обычно
первой в файле). Это поле Word: номера страниц появятся после обновления поля — флаги
`--finalize`/`--pdf` или F9 в Word.

## Абзацы и курсив

Абзац — подряд идущие строки; пустая строка начинает новый абзац. Строки одного абзаца
склеиваются через пробел, поэтому длинный абзац можно переносить как угодно.

Курсив — `_текст_`. Подчёркивание, которое должно остаться символом (имена таблиц,
переменных), экранируется обратной косой чертой: `print\_order` → print_order.
Экранирование работает везде: в тексте, заголовках, списках, ячейках таблиц и подписях.

Ссылка `@id` в тексте заменяется на «рис. N», если рисунок с этим `id` уже встречался выше
(см. [рисунки](#рисунки-и-схемы-drawio)).

## Заголовки

```markdown
### 2.3 Связи между сущностями
```

Количество решёток не важно: уровень определяется номером в начале текста —
`2` → первый уровень, `2.3` → второй, `2.3.1` → третий; подраздел приложения `А.1` —
второй, `А.1.2` — третий; заголовок без номера (ВВЕДЕНИЕ, ПРИЛОЖЕНИЕ А) — первый уровень. Заголовки первого уровня выводятся прописными
буквами, первого и второго — по центру, остальные — слева. В оглавление попадают заголовки
до четвёртого уровня.

## Списки

```markdown
- маркированный пункт
- ещё пункт

1. нумерованный пункт
2. ещё пункт
```

Маркеры: `-`, `–`, `—`, `*`, `+`; нумерация: `1.` или `1)`. Каждый пункт пишется **одной
строкой** — перенос строки внутри пункта заканчивает список. Список заканчивается пустой строкой.

## Таблицы

```markdown
Таблица — Характеристика сущностей
| Сущность | Тип | Назначение |
|---|---|---|
| Пользователь | сильная | учётная запись |
| Модель | сильная | карточка 3D-модели |
```

- Подпись `Таблица — Название` пишется строкой **непосредственно перед** таблицей, без пустой
  строки. Номер проставляется автоматически; число в подписи (`Таблица 5 — …`)
  игнорируется. Подпись `Таблица — …` над HTML-таблицей тоже работает.
- Порядок номеров задаёт тип документа (параметр `нумерация_объектов`, см.
  [document-types.md](document-types.md)): `сквозная` — 1, 2, 3; `по разделам` — 2.1, 2.2;
  `по подразделам` (курсовая) — в разделе 2 вне подразделов 2.1, 2.2, в подразделе 3.2 —
  3.2.1, 3.2.2, в приложении А — А.1, в его подразделе А.1 — А.1.1. Объекты во ВВЕДЕНИИ,
  ЗАКЛЮЧЕНИИ и других разделах без номера получают 1, 2… Так же нумеруются рисунки и формулы.
- Таблица без подписи выводится без номера и не занимает номер — так оформляют реквизиты
  договора или прайс-лист. В отчётах по ГОСТ подпись у таблицы нужна всегда.
- Первая строка таблицы — заголовок: он выводится жирным и повторяется на каждой странице.
- Ширина колонок подбирается по содержимому. Если длинные слова не помещаются, шрифт таблицы
  уменьшается до 10 pt.
- Символ `|` внутри ячейки экранируется: `\|`. Формула в ячейке — `$S = \pi r^2$`.
- Подписи «Продолжение таблицы N» по ГОСТ ставит доводка в Word (флаги `--finalize`, `--pdf`): Word делит
  таблицу по фактической границе страницы, а скрипт добавляет подпись и повторяет шапку.

Объединение ячеек, выравнивание и прозрачные таблицы — в [html-tables.md](html-tables.md).

## Рисунки и схемы draw.io

```markdown
![Функциональная структура системы](img/structure.png)
![Диаграмма потоков данных](img/schemes.drawio#2)
![Концептуальная модель](img/schemes.drawio#ER-модель){#er landscape}
```

- Подпись в квадратных скобках превращается в «Рисунок N — Подпись» под рисунком; первая буква
  делается заглавной. Номера — как у таблиц (см. `нумерация_объектов`).
- Относительный путь ищется по очереди в папке пакета `MarkToGost/`, в `input/` и в корне
  проекта; можно указать абсолютный путь.
- Схема draw.io: `файл.drawio#N` — страница по номеру (с 1), `файл.drawio#Имя` — по названию
  вкладки, без `#` — первая страница. Страница экспортируется в PNG при сборке (нужен draw.io
  Desktop) и кешируется в `output/.drawio_cache`, пока файл схемы не изменится.
- Атрибуты в фигурных скобках после рисунка, через пробел:
  - `#id` — идентификатор для ссылок `@id` в тексте;
  - `landscape` — рисунок размещается на отдельной альбомной странице на всю её ширину.
    Несколько альбомных рисунков подряд делят один альбомный раздел, по рисунку на страницу.
- Рисунок вписывается в страницу по высоте; ширина книжного рисунка — доля ширины текста
  (`--image-width`, по умолчанию 0,7).

## Формулы

```markdown
$$
P = \frac{m \cdot c}{100}
$$

где $P$ — стоимость печати, ₽;
$m$ — масса детали, г;
$c$ — цена материала за килограмм, ₽.
```

- Блочная формула заключается в `$$`. Она вставляется как редактируемая формула Word и
  нумеруется справа: (1), (2)…
- Строки, следующие сразу за формулой (или после одной пустой строки, если они начинаются с
  «где» или `$`), считаются пояснением; в них работают формулы `$…$`.
- Для формул нужен Pandoc. Проверить окружение: `python MarkToGost/formula_renderer.py`.

## Блоки кода

````markdown
```sql
SELECT id, name FROM model WHERE is_free;
```
````

Код выводится моноширинным шрифтом как есть — отступы и пустые строки сохраняются. Язык после
```` ``` ```` необязателен. Размер шрифта и интервал задаются параметрами `--code-font-size` и
`--code-line-spacing`; для длинных листингов удобно `--code-font-size 10 --code-line-spacing 1.0`.

## Вставные листы

Отдельной строкой в нужном месте текста вставляется лист из DOCX-шаблона с полями `{{имя}}`:

```markdown
{{лист: шаблоны/справка.docx}}
{{лист: шаблоны/справка.docx | без номера}}
```

Лист начинается с новой страницы, после него текст продолжается тоже с новой страницы.
Поля заполняются из шапки документа и `marktogost.yaml`. Листы, место которых задаётся
в шапке или профиле (титульный, задание, отзыв перед приложениями), описаны в
[document-types.md](document-types.md#вставные-листы-титульный-задание-отзыв-и-другие).

## Сведения об авторе и служебные флаги

В документе с шапкой сведения об авторе задаются полями шапки и попадают на титульный лист
(см. [document-types.md](document-types.md)). Для документов без шапки остаются служебные
строки вида `[//]: # имя = значение` — в текст они не попадают:

| Строка | Действие |
|---|---|
| `[//]: # numerate = false` | не нумеровать страницы |
| `[//]: # use_headings = false` | заголовки — обычные жирные абзацы без стилей Word (в оглавление не попадают) |
| `[//]: # is_table = true` | в конце документа таблица «Выполнил / Проверил» |
| `[//]: # teacher = "Иванов И. И."` | фамилия проверяющего для этой таблицы |

Строки `__ФИО__: Петров П. П.` и `__Группа__: 3а` задают автора. Без `is_table` в начале
документа справа выводится «Выполнил студент: …, Группа: 090302-…»; с `is_table` ФИО попадает
в таблицу подписей.

## Частые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Имя `print_order` выводится как «print» курсивом «order» | `_…_` — курсив | писать `print\_order` |
| Конец раздела «съедает» абзац или выводится `}` | строка абзаца заканчивается на `}` | перенести `}` или переформулировать строку |
| Таблица выводится текстом | подпись или таблица отделены пустой строкой, нет строки `|---|` | подпись — вплотную перед таблицей, вторая строка — разделитель |
| Пункт списка разбит на пункт и абзац | пункт перенесён на вторую строку | писать пункт одной строкой |
| Вместо рисунка «[Ошибка экспорта draw.io …]» | не найден draw.io Desktop или нет страницы | установить draw.io или задать `DRAWIO_PATH`; проверить номер/имя страницы |
| В содержании нет номеров страниц | поле содержания не обновлено | собрать с `--finalize`/`--pdf` или нажать F9 в Word |
